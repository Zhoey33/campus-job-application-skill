# Campus Job Application Skill

面向 Codex Desktop 的端到端校招投递 Skill。它既可以从官网检索岗位，也可以从用户给出的职位直达链接直接开始申请，并负责简历与表单处理、多志愿准备、投后状态回读和飞书台账维护；用户只处理少数必要的人工卡点，并亲自完成最终审核与投递。

## 使用方法

安装后直接在 Codex 中说：

```text
按照校招投递 Skill 的全流程，投一下 XX 公司的校招。
```

也可以在当前请求中指定届次和方向：

```text
按照校招投递 Skill 的全流程，投一下 XX 公司的 2027 届校招，找财务和审计方向的岗位。
```

如果已经知道要投的岗位，直接附上职位详情或申请链接：

```text
按照校招投递 Skill 的全流程，投一下 XX 公司的这个岗位：https://company.example/jobs/123
```

这种方式会跳过全站岗位搜索和岗位确认，登录并核验岗位、届次、地点、开放状态和投递额度后直接填写。

公司以当前请求为准，不会保存为下次的默认公司。

## 工作流程

```text
没有职位链接：初始化 → 登录与额度核验 → 官方岗位检索 → 岗位确认 ┐
有职位直达链接：初始化 → 登录与额度核验 → 直达岗位核验 ────────┤
                                                                └→ 插件批量填写 → 条件式信息补充 → 最终复核 → 用户审核并投递 → 官网状态核验 → 台账回读
```

### 最多四个业务人工卡点

| 卡点 | 用户操作 | 后续自动执行 |
|---|---|---|
| 登录 | 完成扫码、验证码、密码输入或浏览器权限确认 | 核验登录状态、投递上限、已投数和剩余额度 |
| 岗位确认 | 仅在没有职位直达链接时，确认目标岗位和志愿顺序 | 准备整组志愿并填写、校验表单 |
| 信息补充 | 存在未知字段或申请声明时，一次回答当前可准备志愿的全部问题；敏感信息在本地页面填写 | 写入答案、处理授权控件并复核受影响区域，完整缺口队列清零后进入最终复核 |
| 审核与投递 | 在保留的官网页面审核表单，并亲自点击最终投递 | 核验每个志愿的官网状态并更新台账 |

无法从现有资料确定个人事实时，Skill 会先扫描当前可准备的全部志愿和区块，再在最终审核前集中提问；最终审核本身不再夹带填写问题。其余浏览器操作由 Skill 完成。

## 自动能力

| 模块 | 行为 |
|---|---|
| 岗位入口 | 有职位直达链接时只核验该岗位并直接填表；没有链接时从官方系统完整检索，再确认岗位 |
| 子 Agent 分工 | 岗位 Search 与信息填写使用两个不同子 Agent；主 Agent 只传精简岗位事实，避免搜索历史在填表阶段触发压缩 |
| 表单填写 | 上传 PDF、触发网站简历解析，调用“来个简历”填写并复核组件、附件和必填项 |
| 批量与读取 | 预建重复记录行后只运行一次整页填写；按固定 Computer Use 模板处理区块，仅在关键节点读取完整页面状态 |
| 缺口队列 | 统一管理记录错误、漏填、组件、附件、用户字段和声明授权，局部修复并在交审前清零 |
| 提交前证据 | 为每个志愿生成不含敏感值、明确`submitted: false`的状态快照，再交给用户审核 |
| 字数限制 | 先读取页面限制，忠实压缩超限文本，再按网站计数器和校验结果复核 |
| 多志愿 | 第一志愿完整填写；后续志愿复用共享档案。若共享要在首志愿投递后才生效，则先交给用户审核投递首志愿，再准备剩余志愿 |
| 内推码 | 第一志愿从小红书等公开来源查找并验证；后续志愿复用，不重复搜索 |
| 页面保留 | 未提交、待审核或受阻的申请表保持打开，不刷新或导航离开，避免已填内容丢失 |
| 结果记录 | 用户投递后逐志愿回读官网状态、重新检查额度，并维护飞书个人台账 |

Skill 不会把第一志愿成功当作整组成功。出现新必填事实、验证码、额度或顺序变化、岗位失效或提交异常时才会暂停。

通常全部志愿可以在一次人工投递检查点统一审核；若招聘系统要在第一志愿投递后才开放共享候选人档案，检查点会分阶段进行。后续阶段只审核岗位和附件差异，不重复审核已经确认的个人信息。

## 首次运行

### 依赖

- Codex Desktop、Computer Use 和 Chrome；
- 官方 [`lark-cli`](https://github.com/larksuite/cli) 及所需飞书 Skills；
- Chrome 扩展[“来个简历”](https://cv.playoffer.cn/)；
- 配套 Skill：[laige-resume-autofill](https://github.com/Zhoey33/laige-resume-autofill-skill)。

Skill 会检查这些依赖，并在需要时引导完成安装、登录和授权。

### 首次提供的信息

- 目标届次或毕业年份；
- 默认岗位方向和关键词；
- 飞书个人投递台账；
- 本地资料文件夹绝对路径。

请提前把 PDF 简历、证件照、成绩单、证书和其他证明材料放在同一个本地文件夹。只需提供文件夹路径，不必逐个提供文件路径；同类文件存在多个且无法判断时，Skill 才会请你选择。

首次初始化会生成本地 `context.md` 和 `references/current-profile-field-map.md`。后续运行会复用有效信息，不重复询问。

## 安装

```bash
git clone https://github.com/Zhoey33/campus-job-application-skill.git ~/.codex/skills/campus-job-application-workflow
git clone https://github.com/Zhoey33/laige-resume-autofill-skill.git ~/.codex/skills/laige-resume-autofill
```

两项安装完成后，重新启动 Codex 或刷新 Skills。

## 隐私与边界

- 最终表单审核和点击投递始终由用户亲自完成。Skill 不代点最终提交；用户投递后，Skill 只核验官网状态并维护台账。
- 用户要求投递或确认企业、岗位和志愿后，会直接填写官方申请表、上传已确定材料、调用插件并接受准备申请所必需的平台隐私条款，不再额外询问“确认填写”；真实性及额外可选授权、最终提交仍由用户处理。
- Skill 不编造个人经历、成绩、证书、内推码、推荐人或推荐关系，也不会通过私信、加群、付费或提交个人信息换取内推码。
- `context.md`、`references/current-profile-field-map.md` 和 `references/supplemental-information.md` 已被 `.gitignore` 排除，不会上传到公开仓库。
- 不要在 Issue、提交信息或示例中粘贴简历内容、联系方式、飞书私有链接或本地路径。
