# 首次初始化

仅在`context.md`不存在、初始化未完成或必填项缺失时读取。目标是在真正找岗前一次性准备依赖、取得用户默认输入，并生成可复用的本地私有上下文。

## 1. 检查并准备 lark-cli

先运行`command -v lark-cli`。已安装时运行`lark-cli --version`和`lark-cli auth status --json --verify`，记录版本、用户身份和认证状态；不要因为已安装就重复安装或重新登录。

未安装时：

1. 检查`node`与`npm`是否可用；官方 npm 包要求 Node.js 16 或更高版本。
2. 当前初始化请求允许准备依赖且宿主允许全局安装时，运行`npm install -g @larksuite/cli`；若宿主要求批准或缺少系统写入权限，只请求完成这一项所需的最小确认。
3. 安装后运行`lark-cli --version`确认命令真实可用。
4. 若缺少配套的`lark-shared`、`lark-wiki`或`lark-sheets` Skill，运行`npx -y skills add larksuite/cli -g -y`并重新检查。

若 CLI 尚未配置，按`lark-shared`的首次配置规则运行`lark-cli config init --new`；需要用户打开链接、扫码或授权时，把官方链接和二维码交给用户完成。随后以用户身份完成台账所需的最小授权，并用`lark-cli auth status --json --verify`确认。不得保存 appSecret、access token、refresh token、验证码或 device code 到上下文。

## 2. 检查并准备“来个简历”

使用 Computer Use 检查 Chrome 扩展页或真实网页上是否存在“来个简历”。不要仅凭某个扩展 ID 判断，因为商店版本可能变化。

未安装时，打开官方[安装与帮助页](https://cv.playoffer.cn/help)，根据当前 Chrome 环境进入官方商店安装入口并完成安装。安装扩展会触发浏览器权限确认时，停下让用户确认浏览器原生弹窗。

安装后打开官方[首次使用指引](https://cv.playoffer.cn/help/first_reference)，让用户完成以下账户相关步骤：

1. 扫码登录并确认插件同步成功；
2. 在插件中导入或编辑一份完整简历档案；
3. 选择本次投递默认使用的档案；
4. 在官方示例表单或真实招聘表中确认`继续填写`、`选区填写`和`辅助填写`可见。

登录、扫码、账号选择和档案内容确认必须由用户完成；Agent 在用户完成后自行复核插件状态。

## 3. 一次性取得默认输入

在一个简洁问题中取得并确认可跨任务复用的信息：

- 目标届次或毕业年份；
- 要检索的岗位方向和关键词；
- 飞书个人投递台账链接，以及已知时的标题和底层类型；
- 本地求职资料文件夹绝对路径；
- 可选的企业入口线索表、是否需要查公开内推码等偏好。

询问路径时提醒用户：先把当前简历 PDF、证件照、成绩单、语言或资格证书以及其他可能用于网申的证明文件放到同一个本地资料文件夹，然后只提供该文件夹的绝对路径即可。

检查文件夹存在、可读且确为目录。只列出目录内的文件名、扩展名和必要元数据，建立简历与附件清单，不读取文件正文。只有一个明确的简历 PDF 时，将其绝对路径写入`context.md`作为已解析的默认简历；有多个合理候选且无法从文件名区分时，只向用户列出候选文件名并询问选择哪一个。不得搜索资料文件夹之外的位置。

## 4. 写入本地 context.md

从[上下文模板](context-template.md)创建 Skill 根目录下的`context.md`，写入用户确认值、依赖状态和更新时间。若[补充信息库](supplemental-information.md)不存在，同时从[补充信息库模板](supplemental-information-template.md)创建空白本地文件。初始化全部完成后才把`初始化完成`设为`是`。

`context.md`、`supplemental-information.md`和实际字段地图都已由`.gitignore`排除。不得把其中的个人路径、飞书链接、求职偏好或申请事实复制到 README、模板、示例、提交信息或公开 Issue。

后续调用先读取上下文并复用。用户提供新值时只更新对应字段及更新时间；不要为了“确认一下”重复询问未发生变化的内容。

公司不属于首次初始化或持久化字段。每次从用户当前请求中提取本次要处理的公司，例如“帮我投一下 XXX 公司的秋招”；不要把当前公司写入`context.md`供下次默认复用。

## 5. 生成 current-profile-field-map.md

插件设置完成后，打开官方示例表单或一个可使用插件的招聘表单，进入`辅助填写 → 简历闪填`，按[字段地图模板](current-profile-field-map-template.md)生成`references/current-profile-field-map.md`。

至少记录：

- 生成时间和插件中当前选定档案的可识别名称；
- 分类名称和各分类可用字段；
- 教育、项目、实习、获奖、校园经历等重复模块的记录数量和可识别标题；
- 常用网页字段的搜索关键词与同义词；
- 已观察到的字段缺失、命名差异或高风险映射。

字段地图用于定位，不作为字段值的权威副本。不要记录身份证号、手机号、邮箱、账号凭据或其他没有定位价值的原始值。完成后在`context.md`记录地图路径、档案名称和更新时间。

切换插件档案、档案结构发生明显变化或地图与当前插件不一致时，重新生成；正常后续投递不重复跑完整地图。
