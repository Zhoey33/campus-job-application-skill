# 网申表单填写与复核

本阶段由岗位确认后单独新建的 Form Agent 执行。它只接收公司、登录与额度状态、已确认志愿顺序，以及每岗名称、职位 ID、地点和原始直达链接；不继承岗位 Search Agent 的长历史，也不重新执行岗位分类、关键词检索、翻页覆盖或岗位推荐。若申请页显示的企业、岗位、届次、地点或开放状态与交接包冲突，停止填写并把差异交回主 Agent，不自行重跑 Search 阶段。

进入正式申请表时读取本参考、[表单缺口队列](form-gap-queue.md)和[Computer Use 操作模板](computer-use-operations.md)，同时读取本地[`context.md`](../context.md)、存在时的[`current-profile-field-map.md`](current-profile-field-map.md)和[补充信息库](supplemental-information.md)，并加载`computer-use`与`$laige-resume-autofill`。

## 界面操作与插件分工

浏览器中的导航、标签整理、页面读取、展开、选择、滚动、上传状态核对、来个简历插件操作和表单视觉复核统一使用 Computer Use。来个简历负责复用已选档案和完成整体、选区或字段级的内容填写；不要手工重填插件可可靠提供的简历内容。

本流程不要启动 Playwright MCP、Chrome DOM 控制或扩展中继连接页，也不要打开`chrome-extension://.../connect.html`，不循环重试浏览器连接。

### 页面状态读取预算

只在申请页首次进入、网站解析完成、插件批量动作结束、最终交审前或故障恢复时读取足以覆盖当前表单的完整状态。其余操作（包括用户补充信息后的回填）按稳定区块成组执行，再读取受影响区域、控件或校验提示；未发生页面变化的已验证状态直接复用，不因每次点击、输入或滚动都重新读取整页。

- 同一页面状态不同时获取完整可访问性树和截图；文字与控件状态足够时不截图，只有空间关系、拖框、裁剪或视觉结果无法由结构化状态判断时才截取最小区域。
- 一组操作只包含结果可预期、失败可从局部状态识别且不会跨页面导航的动作。导航、弹窗、动态分支、插件终态和保存结果出现后先观察，再决定下一组。
- 元素标识或坐标失效时先刷新受影响区域后重试一次；连续失败再做一次完整状态读取并改用有区别的定位方式，不用旧标识、旧坐标或同一错误调用循环尝试。
- 完整状态只保留当前决策所需的字段、错误、模块数量和可见文本；回传时不携带整页树、逐步点击日志或重复截图。

## 填表门槛

进入上传或填写前确认：

- 申请表对应的企业、职位、届次和志愿顺序正确；
- `context.md`中的本地资料文件夹存在且可读，已从中确定本次使用的简历 PDF；多个候选无法区分时只询问用户选择哪个文件，不要求用户重新提供完整文件路径；
- 当前 Chrome 保留必要登录状态；
- 来个简历在真实申请页可打开，已登录并选中正确档案。

用户确认当前企业、岗位和志愿，或明确要求填写当前申请表，即授权在该任务范围内通过官方招聘网页和“来个简历”写入申请资料并上传已确定的 PDF 或附件。直接开始准备表单，不再询问“外部写入授权”“确认填写”，也不为`继续填写`、`选区填写`、`简历闪填`分别提问。新增公司、未选岗位、范围外材料或其他目的地不在授权范围内。最终表单审核和点击投递始终由用户亲自完成，Agent 不接受代为提交的授权。

Agent 应自行检查扩展和插件状态，不能要求用户代为确认。通过 Computer Use 检查 Chrome 扩展页或真实申请页上的“来个简历”入口、插件工具、当前档案和一次实际状态。已安装但被禁用且现有浏览器能力允许恢复时，在当前网申任务已授权使用该插件的范围内自行启用并复核。

只有插件确实缺失、需要安装或登录账号、浏览器策略禁止自动操作，且已尝试真实申请页验证和当前可用的浏览器回退后，才请求用户完成最小必要动作。插件不可用只把当前公司填表标为`受阻`，不影响岗位检索和已取得的链接。

## 标签与共享档案

每家公司使用独立 Chrome 标签组，保留职位详情、申请表、个人中心和必要来源页。Agent 自己创建、整理和改名，不让用户代为开页或移动标签。标签组使用`公司｜阶段`：`待登录`、`岗位待审查`、`填写中`、`待补充信息`、`待审查`、`待用户投递`、`提交待确认`、`已提交`或`受阻`。

申请表一旦开始上传或填写，在官网确认提交成功或用户明确放弃之前，必须保留原标签和当前页面：

- 不关闭标签、刷新页面、后退、导航到其他网址或把该标签复用于职位详情、个人中心和下一志愿；这些内容一律新开标签。
- 不假设网站会保存输入。即使页面显示自动保存或已保存，也保留原申请页直到提交成功并完成官网回读。
- 等待用户审核、验证码、补充事实、工具恢复或子 Agent 续派时，先确认标签仍在、岗位正确且已填内容仍可见，再释放浏览器控制。
- 必须重新载入才能继续时，先使用页面提供的保存草稿功能并确认保存成功；没有可验证草稿时暂停并说明刷新可能丢失内容，不能自行冒险重载。

Form 阶段最多保留一个申请概览或模块导航页和一个当前编辑页；需要返回概览时复用同一个概览标签，不为每个教育、实习、项目或家庭记录重复新建并重新输入相同 URL。模块保存并验证后关闭该模块不再需要的临时页；最终交审前只保留能证明申请状态和供用户审核的必要页面，阶段新开的无用概览、重复编辑页和中间跳转页全部关闭。
- 只有官网已明确提交成功并保留申请记录，或用户明确要求放弃该申请时，才可以关闭对应表单标签。

同一招聘系统可能让多个志愿共用候选人档案。第二个岗位前先判断是否共用`个人中心`或`我的简历`：

- 共用时只在第一个志愿完整填写和复核个人信息、教育、经历、简历与通用附件并确认保存成功。后续志愿复用已保存档案，不重复上传、解析简历或运行整页插件，避免覆盖、重复经历和无效耗时。
- 后续志愿仍要核对企业、岗位、志愿序号和共享档案是否真实带入，并处理期望地点、岗位问答和岗位专属附件等差异项；直接复用第一志愿已经验证的内推码，不重新搜索内推信息。共享字段出现空白、过期或校验错误时才修复受影响部分。
- 第二志愿在第一志愿提交前没有继承个人信息时，先判断它是独立申请表，还是网站只有在首志愿提交后才创建或共享候选人档案。尚不能确认时不要立即完整重填，把它标记为`待首志愿提交解锁`并先交审第一志愿。
- 第一志愿经用户审核并提交成功后，重新从个人中心进入第二志愿并检查共享字段、简历、通用附件和内推码。此时能够继承就只填写岗位差异，不再次运行整页插件或要求用户重复审核个人信息；仍不能继承且官网结构已证明相互独立时，才完整填写和复核。
- 官网在提交第一志愿前已经明确显示各岗位档案彼此独立时，不必为了测试共享而提前提交；按独立申请表分别填写。
- 修改共享档案可能影响所有关联岗位；人工审查后再修改时说明影响并重新复核相关岗位。
- 每个志愿仍分别记录链接、顺序、状态和提交结果。

## 多志愿人工投递与回读

通过信息补充门槛后，表单检查点应一次列出当前公司全部已确认志愿及其准备状态，并把对应申请页保持打开交给用户审核。Agent 不点击`提交简历`、`预览并提交`、`确认投递`或同义最终按钮；用户即使明确说“授权提交”，也只表示可以进入人工审核投递卡点，不授权 Agent 代点。

- 后续志愿因`待首志愿提交解锁`尚未准备时，先把第一志愿交给用户审核并投递。用户说明已完成后，Form Agent 回读官网状态；首志愿确认成功再测试共享档案，准备后续岗位差异。出现新增未知项时先执行信息补充检查点，清零后再把剩余志愿交给用户进行下一轮人工审核投递；第二轮不重复展示已经确认的个人信息，只列已完成的岗位差异、附件差异和内推状态。
- 官网用一个按钮同时提交整组志愿时，Form Agent 在交接前核对最终排序和数量；由用户点击整组提交。用户完成后，Form Agent 在个人中心逐项确认所有志愿记录。
- 官网要求逐个提交时，由用户按确认顺序点击每个最终提交按钮。用户说明完成后，Form Agent 逐项读取申请编号或个人中心记录，并重新检查已投数、剩余额度和下一志愿是否仍有效；不得替用户点击下一志愿的提交按钮。
- 后续志愿只复用共享档案且没有新增实质字段时，仍由用户亲自做最终审核和投递。若出现新的必填事实、不同附件或无法自动决定的岗位问题，先退回信息补充门槛；验证码、额度或顺序变化、岗位失效、提交失败或成功状态不明时，在受影响志愿前暂停并报告准确状态。
- 第一志愿成功不代表后续志愿成功。分别回传每个志愿的官网证据和状态，未执行、受阻或失败的志愿保持对应状态。

## 上传与插件接管

上传前不在本地解析、渲染、OCR 或逐项核验 PDF 内容，也不创建独立的简历核验子 Agent。直接上传从本地资料文件夹确定的 PDF 文件，核对页面文件名和上传状态；不要自行转换或改用其他格式。

上传后若网站显示`简历解析`、`一键解析`或同义按钮，必须点击一次并等待网站明确完成解析；网站自动开始解析时等待完成，不重复触发。解析完成后只检查页面是否生成必要模块、是否出现明显重复或解析失败提示，不另做 PDF 内容核验。随后再启动来个简历，避免网站解析与插件并发覆盖或重复。

遵循`$laige-resume-autofill`的插件接管门槛：使用 Computer Use 确认蓝色闪电入口、可用工具和正确档案，再通过当前可见插件面板运行整体填写。重复记录和字段定位优先复用`current-profile-field-map.md`；其中的网站映射只在招聘系统、页面语义和控件类型一致时复用。档案已切换，或网页标签、控件、字段语义与地图不一致时，只重新验证并更新受影响映射，不重跑整份地图。表单内容以用户当前选择、已确认补充信息和来个简历当前正确档案为准，不为填表额外解析 PDF。

运行插件前先扫描区块结构、重复记录数量和可见格式限制，一次补建全部有可靠来源的重复记录行。然后只运行一次`继续填写`完成整页首轮映射；除非页面被重建、档案发生实质切换，或插件明确未开始/失败且原因已经纠正，不重复整页填写。

重复记录中的删除、垃圾桶、减号或移除按钮默认不可操作。只有完整扫描证明记录确为重复或错误、队列明确要求删除，且当前状态能以标签或记录标题确认目标时才允许执行；不得用旧元素索引、无标签坐标或同位置拖动来打开记录。记录意外消失时立即停止该模块，从同一条已确认插件档案或用户材料恢复一次并完整复核，不能边恢复边继续扫描其他模块。

整体填写后按缺口处理：

1. 连续的大块经历空缺使用`选区填写`，每次只处理一条经历或一个逻辑区域；同一区块的多条记录依次处理，每条只核对标题、顺序和关键字段，不在两条之间重新读取整页。
2. 少量孤立字段使用`辅助填写 → 简历闪填`，先选准确经历记录再选字段。
3. 项目描述是当前用户的强制精确覆盖项，不以缺口检测为前提：`继续填写`结束后，即使网页字段非空、看起来正确或来自官网解析，也要逐条先按项目标题匹配档案记录，再通过`辅助填写 → 简历闪填`选择同一记录的`项目描述`，以`覆盖`方式写入网页同名字段并立即核对。网站没有独立`项目描述`字段时记录为不适用，不得改填到项目职责或项目成果；项目职责、描述和成果不能互换或拼接。
4. 修正错误使用`覆盖`；只有用户明确要保留原文并追加时才用`追加`。
5. 插件无法处理但含义和来源已明确的普通控件按页面区块批量补齐：先完成同一区块内的下拉、单复选、日期和级联项，再统一触发失焦、保存或校验并读取该区块结果。
6. 附件独立批量处理并逐项核对上传状态；不得猜填教育、项目、实习、证书、奖项或未知枚举。

## 缺口队列与信息补充门槛

按[表单缺口队列](form-gap-queue.md)维护唯一的`form_gap_queue`。网站解析和一次插件整体填写后，对当前可准备志愿只做一次完整缺口扫描，分别记录整条记录错误、孤立漏填、网站组件、附件、未知事实、用户选择、敏感本地输入和声明授权；之后严格按队列局部修复，不在每项之间重扫整页。

先处理有可靠来源的自动项，再把`pending_user_fields`和未解决`consent_items`按志愿与区块一次性交给主 Agent。用户回复后只复核受影响区域；最终完整复核发现的新问题仍加入原队列，不另建零散清单。完整队列未清零时不得进入表单检查点。

## 字数限制与文本压缩

填写自我评价、项目描述、工作内容、职责、成果、获奖说明等文本框前，先检查字段标签、帮助文字、占位提示、计数器和已有校验错误，识别最少或最多字符限制。页面没有在填写前显示限制时，整体填写后必须逐一检查文本计数器、截断迹象和超限提示；不能把插件显示`填写完成`当作字数合规。

- 来源文本已符合限制时，才直接使用选区填写或简历闪填。
- 来源文本超限时，不要把长文本原样闪填后放任网站截断。基于同一条正确档案记录生成忠实的精简版本，再用 Computer Use 覆盖目标字段；插件已经写入超限内容时也按此方式修正。
- 压缩时优先保留身份或项目背景、本人职责、关键行动、核心技能和可核实成果，删除重复表达、泛化形容和次要背景。不得新增数字、职责、技术、成果或其他原档案中不存在的事实，也不能把不同经历拼接到一起。
- 不做生硬的尾部截断；保持语义和句子完整。字段同时有最少字符限制时，也必须满足下限，不能用无意义重复内容凑字数。
- 填写后触发页面失焦或校验，重新读取计数器和错误状态。中文、标点、空格和换行如何计数以当前网站的实际计数器与校验结果为准；未确认落在允许范围内时，该字段不能视为完成。

如果压缩会迫使删除可能影响申请含义的关键事实，或存在多个无法判断取舍的版本，把候选精简文本及页面限制交给用户选择；普通的去冗余和不改变事实的压缩由 Agent 自行完成。

## 组件型字段与补充信息

插件完成不代表控件状态已生效。复核下拉框、可搜索选择框、单复选、开关、日期区间、`至今`、动态依赖字段、文件上传、证件照裁剪以及需要网站校验的数字和推荐码。

地点字段从用户当前回答、补充信息库或职位详情取得。级联控件依次选择到网站提供且事实支持的最细层级；若网站提供更细层级但资料不足，不推断，向用户询问。期望工作地点使用当前岗位详情的地点；多地点而表单只允许单选、`全国分配`或`地点待定`却强制选城市时，请用户决定。

反复出现的个性化答案从补充信息库读取，不能把公司或岗位特定答案外推。选择`无/否`后，清空曾被插件填入或条件显示的依赖字段。未知必填项保持空白并加入`pending_user_fields`；按“缺口队列与信息补充门槛”统一询问。用户回答后只把可复用且非敏感的答案按明确适用范围更新到补充信息库，再完成填写。

工作年限不能根据实习时长、教育时间或年龄推断；调剂、城市、方向和岗位问答按用户当前选择或明确适用的补充信息填写。用户选择岗位地点或期望工作地，只能支持相同含义的地点字段，绝不等于同意岗位调剂、全国分配或其他城市；没有对应的明确答案时，把调剂选项加入`pending_user_fields.user_choices`，不得先写入临时默认值并称为“已确认”。成绩及排名保留原始口径，不把百分比、名次和分数相互换算。证件类型需要与用户材料或当前确认一致，证件号码只记录“已由用户本地填写并通过校验”，不得进入字段地图、队列回传或台账。

日期或时间控件优先按可访问元素、可编辑文本、键盘或网站提供的精确选择项操作。遇到只能依赖坐标拖动的多列滚轮时，最多做一次可校准且能立即读回结果的尝试；不能确定目标值与位移关系、一次后仍无法可靠读回，或需要跨较大范围连续拖动时，立即取消错误值并把该控件标记为`requires_local_interaction`，交给用户在保留页面本地完成。不得用连续拖动加截图来搜索目标日期，也不得读取或回传用户本地填写的具体敏感日期。

为上传材料和准备当前申请所必需的招聘平台隐私政策或个人信息处理条款，视为已获投递授权，直接单独勾选并读取真实状态，不设人工卡点。真实性声明，以及可选人才库、营销共享、额外第三方传输、背景调查和类似授权逐项加入`consent_items`，记录页面原文摘要、必填/可选、联动影响和用户选择；用户确认后再单独操作对应控件。不得与普通字段批量点击，也不得把必填隐私条款自动外推为对这些额外授权的同意。

## 推荐方式

页面出现`内推`、`员工推荐`或同义推荐方式时，默认选择该方式以展开真实依赖项，不再为是否采用公开内推增加用户检查点。选择后先读取受影响区域：只有页面真实新增必须填写的推荐码、邀请码或推荐人字段，且当前公司和招聘项目尚无已验证代码时，才从小红书以及其他公开可访问来源寻找适用于当前申请的代码；可把公开信息核验交给只读子 Agent，与不控制浏览器的工作并行。若没有新增代码或推荐人字段，直接保留该选择并继续表单，不启动外部检索；已误启动时立即停止，且不保留它打开的搜索标签。

- 使用`公司 + 目标届次 + 校招 + 内推码/推荐码/邀请码`等组合搜索。优先打开近期的小红书原帖，同时检查至少一个其他可公开访问的来源，例如企业或员工公开帖、校园招聘社区、公众号公开文章或搜索结果指向的原始页面；不能只根据转载标题或搜索摘要抄码。
- 对每个候选核对发布日期、公司、招聘届次、岗位类别、地区或业务线、有效期和完整代码。优先采用范围最明确、时间最近且与当前申请直接匹配的候选。
- 只使用公开展示且明确用于招聘内推的真实代码，以及原帖明确要求随代码填写的公开推荐标识。不得为获取代码私信、关注、加群、付费、提交个人信息或向发布者发送简历；不得猜测推荐人姓名、工号、部门或与申请人的关系。
- 填写后触发网站校验，确认代码被接受且推荐方式保持为`内推`。代码明确无效时换用下一个经过核验的候选，不重复尝试同一代码，也不尝试无来源的随机代码。
- 第一志愿的代码被网站接受后，将代码、来源和适用范围保存在当前公司的投递队列，并传给同一公司执行 Agent。第二及后续志愿直接填写该代码并检查网站是否接受，不再搜索小红书或其他来源。
- 只有后续志愿明确拒绝该代码，或原始来源明确限定到第一志愿的岗位、地区或业务线且当前志愿不在范围内时，才重新核验一次新的内推码；不能仅因为切换了志愿就重复搜索。
- 只有已检查小红书和至少一个其他合理公开来源仍没有合格候选，或网站限制继续验证时，才把内推标为`受阻`并报告已查来源和准确原因；保持申请未提交，不伪造信息或悄悄改选普通网申。
- 保存实际采用的代码、原始来源链接、发布日期、适用届次和范围；在投递队列、表单检查点以及台账存在对应列时记录这些信息。

## 附件与完整性复核

插件不会可靠完成实际上传。根据本地资料文件夹中的附件清单，逐一确认简历 PDF、证件照及网站要求的成绩单、语言、资格或其他证明文件真实存在，页面文件名正确且上传成功。只上传当前页面明确要求或用户指定的材料；同类文件有多个且无法区分时询问用户。多个附件位置分别核对。

信息补充门槛通过后，交审前至少检查：

- 必填项有有效值，重复模块数量正确且无重复；
- 有字数限制的字段均落在页面允许范围内，没有静默截断或残留超限提示；
- 学校、专业、学历、公司、职位、职责、成果和地点没有错位；
- 起止时间与`至今`符合来源；
- 工作年限、调剂、成绩及排名、证件类型和证件号码状态符合已确认来源，且没有从其他经历推断；
- 下拉框、单选和级联地点是真实选中而非仅显示文本；
- 附件真实上传；插件警告对应可解释的未知或非必填项；
- 必需声明真实选中，可选声明与用户选择一致，没有捆绑外推；
- 推荐方式与实际代码一致，岗位和志愿顺序未被页面跳转改变；
- 补充信息的适用范围正确，选择`无/否`后的依赖字段已清空。

用 Computer Use 核对当前页面的空字段、校验提示和模块数量。修正后重新执行受影响部分的复核。

## 提交前状态快照

最终完整复核通过后，为每个待交审志愿生成一份紧凑快照并回传主 Agent。快照保存页面当时可验证的状态，不包含身份证件号码、联系方式、附件内容或其他敏感值：

```json
{
  "observed_at": "",
  "company": "",
  "recruitment_project": "",
  "job_id": "",
  "job": "",
  "location": "",
  "order": 1,
  "application_url": "",
  "shared_profile_reused": false,
  "critical_choices": {
    "adjustment": "",
    "job_specific_choices": []
  },
  "attachments": {
    "resume_uploaded": false,
    "photo_uploaded": null,
    "other_required": []
  },
  "required_fields_valid": false,
  "website_components_valid": false,
  "long_text_valid": false,
  "sensitive_fields_present_and_valid": false,
  "consent_items_resolved": false,
  "autosave_state": "confirmed | unavailable | failed",
  "form_gap_queue_open": 0,
  "submitted": false

```

`autosave_state`只能写页面实际显示的状态；网站没有可验证自动保存时写`unavailable`，不能猜测。快照只证明提交前页面状态，不替代用户提交后的官网回读；官网未显示的字段不得声称在提交后得到确认。

## 表单检查点

只有完整`form_gap_queue`清零、完整性复核通过且逐志愿快照已经生成，才能把标签组改为`公司｜待用户投递`。保留职位原链接和仍含已填内容的申请表，并一次说明全部已确认志愿及顺序、每个志愿的准备状态、共享个人档案状态、岗位专属字段、附件状态、声明状态、推荐方式和来源，以及尚未点击最终提交；不得在这一检查点首次询问任何填写信息。交接前再次确认所有未提交表单标签仍然打开且内容未丢失，然后释放浏览器控制，请用户亲自审核并点击最终投递。用户要求修改时由 Form Agent 修正并再次复核；修改产生新未知项时退回信息补充门槛并重新生成受影响快照。用户说明已经投递后，Form Agent 只回读官网状态、申请编号和剩余额度，不再点击提交或修改已投志愿。
