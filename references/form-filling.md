# 网申表单填写与复核

进入正式申请表时读取本参考，同时读取本地[`context.md`](../context.md)、存在时的[`current-profile-field-map.md`](current-profile-field-map.md)和[补充信息库](supplemental-information.md)，并加载`computer-use`与`$laige-resume-autofill`。

## 界面操作与插件分工

浏览器中的导航、标签整理、页面读取、展开、选择、滚动、上传状态核对、来个简历插件操作和表单视觉复核统一使用 Computer Use，按当前界面状态逐步操作。来个简历负责复用已选档案和完成整体、选区或字段级的内容填写；不要手工重填插件可可靠提供的简历内容。

本流程不要启动 Playwright MCP、Chrome DOM 控制或扩展中继连接页，也不要打开`chrome-extension://.../connect.html`。每次界面变化后重新读取当前状态，不循环重试浏览器连接。

## 填表门槛

进入上传或填写前确认：

- 申请表对应的企业、职位、届次和志愿顺序正确；
- `context.md`中的本地资料文件夹存在且可读，已从中确定本次使用的简历 PDF；多个候选无法区分时只询问用户选择哪个文件，不要求用户重新提供完整文件路径；
- 当前 Chrome 保留必要登录状态；
- 来个简历在真实申请页可打开，已登录并选中正确档案。

用户确认了当前企业、岗位和志愿，或明确要求填写当前申请表后，即可上传其指定 PDF，并把“来个简历”档案中的姓名、联系方式、教育、实习、项目、技能、奖项、证书等信息填写到对应申请中；不要再向用户发送单独的上传或填写授权问题。最终提交仍按独立检查点处理。

Agent 应自行检查扩展和插件状态，不能要求用户代为确认。通过 Computer Use 检查 Chrome 扩展页或真实申请页上的“来个简历”入口、插件工具、当前档案和一次实际状态。已安装但被禁用且现有浏览器能力允许恢复时，在当前网申任务已授权使用该插件的范围内自行启用并复核。

只有插件确实缺失、需要安装或登录账号、浏览器策略禁止自动操作，且已尝试真实申请页验证和当前可用的浏览器回退后，才请求用户完成最小必要动作。插件不可用只把当前公司填表标为`受阻`，不影响岗位检索和已取得的链接。

## 标签与共享档案

每家公司使用独立 Chrome 标签组，保留职位详情、申请表、个人中心和必要来源页。Agent 自己创建、整理和改名，不让用户代为开页或移动标签。标签组使用`公司｜阶段`：`待登录`、`岗位待审查`、`填写中`、`待审查`、`提交待确认`、`已提交`或`受阻`。

同一招聘系统可能让多个志愿共用候选人档案。第二个岗位前先判断是否共用`个人中心`或`我的简历`：

- 共用时只在第一个志愿完整填写和复核个人信息、教育、经历、简历与通用附件并确认保存成功。后续志愿复用已保存档案，不重复上传、解析简历或运行整页插件，避免覆盖、重复经历和无效耗时。
- 后续志愿仍要核对企业、岗位、志愿序号和共享档案是否真实带入，并处理期望地点、岗位问答、岗位专属附件、内推信息等差异项；共享字段出现空白、过期或校验错误时才修复受影响部分。
- 独立申请表或官网明确要求每个岗位单独维护档案时，才分别完整填写和复核。
- 修改共享档案可能影响所有关联岗位；人工审查后再修改时说明影响并重新复核相关岗位。
- 每个志愿仍分别记录链接、顺序、状态和提交结果。

## 多志愿连续提交

表单检查点应一次列出当前公司全部已确认志愿及其准备状态。用户可以在一次回复中明确授权提交这组志愿；授权只覆盖列出的公司、岗位和顺序，不延伸到后来新增或替换的岗位。

- 官网用一个按钮同时提交整组志愿时，提交前核对最终排序和数量，提交后在个人中心逐项确认所有志愿记录，不再重复点击单岗提交。
- 官网要求逐个提交时，按确认顺序执行。每个志愿成功后读取申请编号或个人中心记录，并重新检查已投数、剩余额度和下一志愿是否仍有效；条件不变时直接继续，不新增人工检查点。
- 后续志愿只复用共享档案且没有新增实质字段时，第一志愿后的提交不需要再次审核个人信息。若出现新的必填事实、不同附件、无法自动决定的岗位问题、验证码、额度或顺序变化、岗位失效、提交失败或成功状态不明，则在受影响志愿前暂停。
- 第一志愿成功不代表后续志愿成功。分别回传每个志愿的官网证据和状态，未执行、受阻或失败的志愿保持对应状态。

## 上传与插件接管

上传前不在本地解析、渲染、OCR 或逐项核验 PDF 内容，也不创建独立的简历核验子 Agent。直接上传从本地资料文件夹确定的 PDF 文件，核对页面文件名和上传状态；不要自行转换或改用其他格式。

上传后若网站显示`简历解析`、`一键解析`或同义按钮，必须点击一次并等待网站明确完成解析；网站自动开始解析时等待完成，不重复触发。解析完成后只检查页面是否生成必要模块、是否出现明显重复或解析失败提示，不另做 PDF 内容核验。随后再启动来个简历，避免网站解析与插件并发覆盖或重复。

遵循`$laige-resume-autofill`的插件接管门槛：使用 Computer Use 确认蓝色闪电入口、可用工具和正确档案，再通过当前可见插件面板运行整体填写。重复记录和字段定位优先复用`current-profile-field-map.md`；档案已切换或页面显示与地图不一致时，先更新地图。表单内容以用户当前选择、已确认补充信息和来个简历当前正确档案为准，不为填表额外解析 PDF。

整体填写后按缺口处理：

1. 连续的大块经历空缺使用`选区填写`，每次只处理一条经历或一个逻辑区域，并立即检查重复和错位。
2. 少量孤立字段使用`辅助填写 → 简历闪填`，先选准确经历记录再选字段。
3. 项目描述逐条用对应项目记录的`项目描述`覆盖；项目职责、描述和成果不能互换或拼接。
4. 修正错误使用`覆盖`；只有用户明确要保留原文并追加时才用`追加`。
5. 插件无法处理但含义和来源已明确的普通控件用 Computer Use 补齐；不得猜填教育、项目、实习、证书、奖项或未知枚举。

## 字数限制与文本压缩

填写自我评价、项目描述、工作内容、职责、成果、获奖说明等文本框前，先检查字段标签、帮助文字、占位提示、计数器和已有校验错误，识别最少或最多字符限制。页面没有在填写前显示限制时，整体填写后必须逐一检查文本计数器、截断迹象和超限提示；不能把插件显示`填写完成`当作字数合规。

- 来源文本已符合限制时，才直接使用选区填写或简历闪填。
- 来源文本超限时，不要把长文本原样闪填后放任网站截断。基于同一条正确档案记录生成忠实的精简版本，再用 Computer Use 覆盖目标字段；插件已经写入超限内容时也按此方式修正。
- 压缩时优先保留身份或项目背景、本人职责、关键行动、核心技能和可核实成果，删除重复表达、泛化形容和次要背景。不得新增数字、职责、技术、成果或其他原档案中不存在的事实，也不能把不同经历拼接到一起。
- 不做生硬的尾部截断；保持语义和句子完整。字段同时有最少字符限制时，也必须满足下限，不能用无意义重复内容凑字数。
- 填写后触发页面失焦或校验，重新读取计数器和错误状态。中文、标点、空格和换行如何计数以当前网站的实际计数器与校验结果为准；未确认落在允许范围内时，该字段不能视为完成。

如果压缩会迫使删除可能影响申请含义的关键事实，或存在多个无法判断取舍的版本，把候选精简文本及页面限制交给用户选择；普通的去冗余和不改变事实的压缩由 Agent 自行完成。

## 组件型字段与补充信息

插件完成不代表控件状态已生效。复核下拉框、可搜索选择框、单复选、开关、日期区间、`至今`、动态依赖字段、文件上传、证件照裁剪以及需要网站校验的数字和推荐码。

地点字段从用户当前回答、补充信息库或职位详情取得。级联控件依次选择到网站提供且事实支持的最细层级；若网站提供更细层级但资料不足，不推断，向用户询问。期望工作地点使用当前岗位详情的地点；多地点而表单只允许单选、`全国分配`或`地点待定`却强制选城市时，请用户决定。

反复出现的个性化答案从补充信息库读取，不能把公司或岗位特定答案外推。选择`无/否`后，清空曾被插件填入或条件显示的依赖字段。未知必填项保持空白并提出具体问题；用户回答后更新补充信息库再填写。

## 推荐方式

页面出现`内推`、`员工推荐`或同义推荐方式时，默认选择内推，不再为是否采用公开内推码增加用户检查点。出现内推码、推荐码或邀请码字段时，主动从小红书以及其他公开可访问来源寻找适用于当前申请的代码；可把公开信息核验交给只读子 Agent，与不控制浏览器的工作并行。

- 使用`公司 + 目标届次 + 校招 + 内推码/推荐码/邀请码`等组合搜索。优先打开近期的小红书原帖，同时检查至少一个其他可公开访问的来源，例如企业或员工公开帖、校园招聘社区、公众号公开文章或搜索结果指向的原始页面；不能只根据转载标题或搜索摘要抄码。
- 对每个候选核对发布日期、公司、招聘届次、岗位类别、地区或业务线、有效期和完整代码。优先采用范围最明确、时间最近且与当前申请直接匹配的候选。
- 只使用公开展示且明确用于招聘内推的真实代码，以及原帖明确要求随代码填写的公开推荐标识。不得为获取代码私信、关注、加群、付费、提交个人信息或向发布者发送简历；不得猜测推荐人姓名、工号、部门或与申请人的关系。
- 填写后触发网站校验，确认代码被接受且推荐方式保持为`内推`。代码明确无效时换用下一个经过核验的候选，不重复尝试同一代码，也不尝试无来源的随机代码。
- 只有已检查小红书和至少一个其他合理公开来源仍没有合格候选，或网站限制继续验证时，才把内推标为`受阻`并报告已查来源和准确原因；保持申请未提交，不伪造信息或悄悄改选普通网申。
- 保存实际采用的代码、原始来源链接、发布日期、适用届次和范围；在投递队列、表单检查点以及台账存在对应列时记录这些信息。

## 附件与完整性复核

插件不会可靠完成实际上传。根据本地资料文件夹中的附件清单，逐一确认简历 PDF、证件照及网站要求的成绩单、语言、资格或其他证明文件真实存在，页面文件名正确且上传成功。只上传当前页面明确要求或用户指定的材料；同类文件有多个且无法区分时询问用户。多个附件位置分别核对。

交审前至少检查：

- 必填项有有效值，重复模块数量正确且无重复；
- 有字数限制的字段均落在页面允许范围内，没有静默截断或残留超限提示；
- 学校、专业、学历、公司、职位、职责、成果和地点没有错位；
- 起止时间与`至今`符合来源；
- 下拉框、单选和级联地点是真实选中而非仅显示文本；
- 附件真实上传；插件警告对应可解释的未知或非必填项；
- 推荐方式与实际代码一致，岗位和志愿顺序未被页面跳转改变；
- 补充信息的适用范围正确，选择`无/否`后的依赖字段已清空。

用 Computer Use 核对当前页面的空字段、校验提示和模块数量。修正后重新执行受影响部分的复核。

## 表单检查点

复核完成后把标签组改为`公司｜待审查`，保留职位原链接和申请表，并一次说明全部已确认志愿及顺序、每个志愿的准备状态、共享个人档案状态、岗位专属字段、附件状态、推荐方式和来源、待用户决定字段以及尚未点击最终提交。用户反馈修改后再次复核；用户明确授权整组提交时按“多志愿连续提交”执行。
