# 多 Agent 编排

完整投递或批量投递时读取本参考。目标是让主 Agent 只保留决策、队列、验收和正式台账所需的最小上下文，把网页操作和公司招聘系统执行留在子 Agent 的独立上下文中。

## 角色边界

主 Agent 负责：

- 从用户当前消息和本地上下文确定公司、届次、岗位范围、是否提供明确岗位直达链接、本地资料文件夹及已解析的简历 PDF；任务可能进入填表且资料文件夹缺失时，在开始阶段立即索取；
- 读取当前阶段必需的 Skill 与参考，建立并维护投递队列；
- 给子 Agent 明确公司、阶段、输入、允许动作、停止点和回传格式；
- 汇总子 Agent 结果，检查直接证据，处理岗位确认；Form Agent 直接处理准备申请所必需的招聘平台隐私条款，完成首次扫描后由主 Agent 验收`form_gap_queue`，在最终审核前集中处理待用户字段和其余声明授权，再验收队列清零及逐志愿提交前状态快照；
- 亲自执行正式飞书台账的查重、最小写入、回读和重复检查，不为台账创建子 Agent；
- 在验收通过后推进状态，不因子 Agent 自称完成而直接标记成功。

子 Agent 负责实际执行。可独立形成交付物的任务默认拆出；只有很小、必须立即衔接用户回答或无法形成独立验收结果的动作留给主 Agent。子 Agent 不自行继续分派或扩大任务；确有新的拆分机会时返回主 Agent 统一调度。

## 上下文与等待成本

- 新建子 Agent 时只传公司、阶段、事实输入、授权边界、停止点、当前阶段参考路径和回传格式；使用运行时支持的不继承历史或最小历史继承。不要把整个主会话、完整 Skill 正文或不相关工具目录重复注入子 Agent。
- 主 Agent 已给出必要公共规则时，子 Agent 不再读取完整`SKILL.md`或本编排参考，只读取当前阶段专用参考。只在同一阶段续派原 Agent，并只发送自上次交付后新增的事实和任务；不得用续派跨过岗位 Search 与 Form 阶段。
- 等待子 Agent 时使用事件等待，一次等待覆盖合理时长；状态未变化时不重复读取整条线程、不生成“仍在处理中”的同义更新，也不启动替代检索。只有阶段完成、真实阻塞、需要用户动作或超过预期耗时时才汇报。

需要验证优化效果时按[投递优化指标](optimization-metrics.md)采集。阶段 Agent 只从现有操作记录累计计数并回传一行；主 Agent 只使用运行时直接提供的时间和 usage。不能直接取得的指标保留为空，不额外扫描线程、日志、页面或缓存。

## 默认拆分

| 子任务 | 子 Agent 交付 | 可否并行 |
|---|---|---|
| 单公司登录与岗位入口处理 | 直达路径回传登录与额度状态、每个原链接的企业/岗位/届次/地点/开放状态核验；检索路径回传官方入口、完整匹配岗位、职位 ID、地点、链接、覆盖与缺口 | 使用 Computer Use 时独占浏览器；直达路径不得扩展为全站检索 |
| 申请页确认存在推荐码/内推字段，且当前公司和项目尚无已验证代码时的公开内推信息核验 | 公开来源中的合格候选代码、适用范围、有效期和原始来源；没有合格结果也要明确 | 仅与不控制浏览器的表单准备并行；不得在登录或岗位检索阶段提前创建，同公司后续志愿不得重复创建 |
| 单公司整组志愿填表与复核 | 首志愿完整档案状态、后续志愿共享档案复用状态或`待首志愿提交解锁`证据、完整`form_gap_queue`、逐志愿提交前状态快照和未提交状态 | 使用 Computer Use 时独占浏览器 |
| 用户投递后的官网回读 | 每个志愿的官网成功证据、申请编号或个人中心记录，以及投递后的剩余额度 | 仅在用户明确表示已经亲自完成投递后执行；不得点击最终提交 |

## Search 与 Form 的强制边界

- **岗位 Search Agent**只读取[岗位入口与官方检索](job-search.md)，负责登录、额度核验、直达链接核验或全量岗位检索。其停止点是向主 Agent 交付可验收的岗位事实；不得创建申请草稿、上传附件、调用来个简历或填写申请表。岗位核验需要补查时可续派这个 Agent，但阶段验收完成后不再复用。
- **Form Agent**必须在岗位已经确认后单独新建，并采用不继承 Search Agent 历史的运行方式。它只接收精简交接包，读取[表单填写](form-filling.md)并从已确认的职位原链接进入申请；不得重新执行岗位分类、关键词搜索、全量翻页或岗位推荐。
- Form Agent 在填写阶段内持续持有该公司的表单上下文。用户要求修改、首志愿人工投递后处理后续志愿以及投后官网回读时，优先续派同一个 Form Agent，避免丢失未提交页面和字段状态。Form Agent 永远不点击最终提交。

这条边界同样适用于岗位直达路径：先由 Search Agent 完成链接、登录和额度核验，再由新的 Form Agent 填写。不得为了减少一次创建而把两个阶段合并到同一子 Agent；这会让长岗位页面历史进入填表上下文并触发无效压缩。

Chrome 窗口具有执行会话所有权。当前阶段 Agent 仍在操作时，主 Agent 不得同时操作该窗口或另开重复页面。Search Agent 开始时记录已有标签；完成岗位核验后，只关闭本阶段明确新开且已无用途的搜索结果、重复官网、失败入口和中间跳转标签，保留一个可继续操作的目标公司官方职位页，再明确释放浏览器并回传窗口标题、标签标题、URL、页面阶段及标签清理计数；新 Form Agent 再通过 Google Chrome 应用级界面核对后接管。Form 阶段内续派原 Form Agent 时，从保留的原页面继续。禁止使用 ChatGPT/Codex 的外部 Chrome 标签接管、调试或扩展桥接。控制调用超时后由当前所有者复核实际 URL、标题和页面内容，不能把超时直接上报为网站不可达。

## 主 Agent 台账职责

正式台账始终由主 Agent 操作。需要维护台账时，主 Agent 读取[飞书台账](ledger.md)和本地[`context.md`](../context.md)，按需加载飞书相关 Skill，完成目标资源核验、查重、最小写入、完整回读和重复检查。台账失败只影响台账状态，不把浏览器任务重新收回主上下文，也不临时创建台账子 Agent。

## Computer Use 独占

执行浏览器任务前读取[Computer Use 操作模板](computer-use-operations.md)，按其中公开方法、批量观察和错误恢复模板操作。

所有 Agent 共享本机界面和浏览器状态。同一时刻只允许一个执行 Agent 使用 Computer Use 操作 Chrome；主 Agent 和其他子 Agent 在此期间不得点击、导航、滚动或切换同一浏览器。不同公司的界面任务也串行执行，官方资料检索和其他不控制本机界面的只读任务可以并行。

执行 Agent 接管前说明目标公司和阶段，通过 Google Chrome 应用对象读取窗口并核对标题、当前 URL 和页面内容；完成或受阻时明确释放浏览器。不要让多个自动化方式并发控制同一窗口。只能使用应用级点击、输入、键盘、滚动、截图和可访问性状态；不得调用外部 Chrome 的`getTab`、`createBrowserTab`、标签级`goto`或等价调试接口。

释放浏览器控制不等于保留全部临时页面。执行 Agent 必须保留所有未提交、待审核、等待用户输入或受阻的申请表与登录验证标签，不刷新、不导航离开，也不为整理标签而关闭它们；阶段开始前已有、其他公司或归属不确定的标签也不得关闭。Search 阶段按岗位检索参考关闭自己新开的无用检索标签；Form 阶段只有官网提交成功并完成回读，或用户明确放弃时才能关闭对应申请页。回传标签组名称、对应岗位、当前阶段、页面内容仍在的确认，以及本阶段新开、已关闭、仍保留和因归属不确定未关闭的数量。同一公司续派时优先回到保留的原页面继续。

## 分派内容

主 Agent 的任务说明只传递最小充分上下文，并包含：

- 公司、届次、岗位范围、入口路径和当前阶段；岗位直达路径须附用户提供的原始完整 URL，并明确禁止全站搜索和重复岗位确认；
- 官方登录状态；未登录时先完成登录核验，验证码或扫码返回主 Agent 处理；
- 本地资料文件夹绝对路径、已确定的简历 PDF 和当前申请需要的附件；同类文件仍有多个候选时返回主 Agent 询问用户；
- 已确认的企业、完整志愿列表和准确顺序；这些事实构成当前任务范围内的表单写入、材料上传和插件填写授权，Form Agent 直接为整组申请调用来个简历并为后续志愿复用共享档案，不再设置“外部写入授权”“确认填写”或逐插件功能确认；
- 后续志愿在首志愿人工投递前无法复用时，返回它是独立表单还是`待首志愿提交解锁`的页面证据；后者不得擅自完整重填，先返回主 Agent 把第一志愿交给用户审核投递，官网确认成功后再续派原 Form Agent 复查共享状态；
- 当前公司已验证的内推码、原始来源和适用范围；后续志愿先复用并验证，不重新发起公开内推搜索，只有代码被拒绝或范围明确不适用时返回主 Agent 重新核验；
- 当前已交给用户人工审核投递的精确志愿列表；只有用户明确说明已经完成对应志愿的投递后，Form Agent 才逐项回读，遇到额度、顺序、字段或结果变化时停止；
- 当前保留的未提交表单标签、对应岗位和页面状态；子 Agent 结束任务时不得关闭这些标签，并在回传中确认内容仍在；
- 完整`form_gap_queue`及其记录错误、孤立漏填、网站组件、附件、`pending_user_fields`和页面声明`consent_items`状态；除非某选择立即阻塞页面分支展开，否则先完成全部当前可执行工作和首次扫描，再统一返回主 Agent。用户回答后续派同一 Form Agent 填写、保存和复核，完整队列清零前不得进入最终审核；
- 交审前每个志愿的不含敏感值提交前状态快照；修改影响快照字段时重新生成受影响志愿的快照；
- 必须遵守的用户检查点和停止位置；
- 需要加载的阶段参考与工具 Skill；
- 回传格式和验收所需证据。

分派中直接写出上述最小规则，不要求子 Agent 再读取完整`SKILL.md`或本编排参考；只有阶段参考包含本次必须的细节时才让它读取对应单一文件。

Search Agent 完成后，主 Agent 只把以下精简交接包传给新 Form Agent：公司与招聘项目、已确认登录状态、最大投递数/已投数/剩余额度、准确志愿顺序，以及每岗完整名称、职位 ID、地点和原始直达链接。不要传 Search Agent 的完整对话、页面树、截图集、搜索关键词日志、翻页过程或排除岗位清单。若某项排除理由会直接影响所选岗位，则只传该项结论和最小证据。

不得把某公司的岗位选择扩展给其他公司或未选岗位。最终提交按钮始终留给用户亲自操作；验证码、登录凭据、未知个人事实和会改变志愿的选择均返回主 Agent 处理。

## 精简回传

子 Agent 只回传主 Agent 做决策和验收所需的结构化结果：

1. 当前公司、阶段和状态；
2. 已确认事实及官方链接或页面证据；
3. 实际执行的上传、填写、投后回读或台账写入动作；
4. 覆盖范围和未完成范围；
5. `form_gap_queue`摘要：各分类开放项数量，以及需要用户处理的字段和声明明细；完整清零时明确写 0；
6. 进入交审时附逐志愿提交前状态快照，否则说明尚未生成；
7. 下一项安全动作；
8. 本阶段标签清理结果：新开、已关闭、仍保留、归属不确定未关闭的数量，以及保留的目标页面；
9. 按[投递优化指标](optimization-metrics.md)回传一行阶段计数；只有运行时直接可得时才附耗时和 token 用量。

默认不回传完整 DOM、整页可访问性树、长命令输出、逐步点击记录或全部截图。只有某项结论依赖视觉状态且链接或文字不足以验收时，才附最小必要截图或摘录。主 Agent 不重复执行子 Agent 已完成的全量操作，只抽查会改变结论的关键证据。

## 验收标准

- 岗位入口：两条路径都已确认官方系统登录成功，最大投递数、已投数和剩余额度有登录后证据。直达路径须逐链接确认目标企业、唯一岗位、届次、地点和开放状态，不要求招聘项目全量覆盖；检索路径须确认招聘项目、分类与关键词覆盖、分页或总数、逐岗详情和地点。有缺口时不能称为完整。
- 表单填写：岗位和志愿顺序正确；首志愿的 PDF、网站解析、插件档案、必填和组件状态已复核；后续志愿已确认共享档案真实复用并只补齐岗位差异，或有证据标记为`待首志愿提交解锁`而没有盲目完整重填；首志愿由用户投递后已再次检查共享状态；有字数限制的字段已通过页面校验；页面提供内推方式时，后续志愿复用首志愿已验证代码且未重复搜索，或有可复核的拒绝、不适用或受阻原因；完整`form_gap_queue`已在最终审核前清零，敏感字段已由用户在本地页面完成，必需声明已生效且可选声明符合用户选择；所有交审志愿均有不含敏感值且`submitted:false`的提交前快照，原申请表标签仍打开且已填内容可见。不要求独立的 PDF 内容核验。
- 台账更新：目标记录正确、没有重复行，写入后回读一致。
- 投后核验：已确认最终提交由用户亲自点击；用户说明完成后，对每个志愿分别取得官网成功状态或个人中心申请记录，并核对剩余额度；按钮消失、页面跳转或第一志愿成功不能证明后续志愿成功。

验收不通过时，主 Agent 把岗位或额度缺口续派给原 Search Agent，把表单、附件或投后状态缺口续派给原 Form Agent；不在主上下文中接管其完整执行，也不让一个阶段的 Agent 修复另一个阶段的缺口。连续出现同一工具故障时可换同阶段执行子 Agent 或换可验证路径，但仍遵守 Computer Use 独占规则和原授权边界。
