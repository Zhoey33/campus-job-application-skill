# 岗位入口与官方检索

在核验用户提供的岗位直达链接、定位入口、登录招聘系统、筛选岗位或核实志愿限制时读取本参考。岗位直达与岗位检索是互斥入口；两者都不依赖飞书台账写入或来个简历扩展，并且必须先登录目标企业官方招聘系统。

## 岗位直达路径

用户提供可唯一对应具体职位的详情页或直接申请链接，并明确要求投递时，跳过“检索范围”和“岗位检查点输出”：

1. 保留并打开用户给出的原始完整 URL，先完成官方招聘系统登录；登录跳转后回到该职位原链接。
2. 确认最终页面属于目标企业的官方招聘系统或其企业专属招聘服务商路径，并能唯一识别该职位。
3. 从详情页核实完整岗位名称、职位 ID（页面可见时）、届次、工作地点、职责、要求和当前可申请状态；从投递须知或个人中心核实最大投递数、已投数和剩余额度。
4. 事实与用户要求一致且额度允许时，保留原链接作为该志愿证据并直接进入申请表；不再搜索相似岗位、不证明岗位全集，也不触发岗位确认检查点。

用户同时提供多个直达链接时逐个核实，按用户明确顺序建立志愿。列表页、搜索页、公司首页、第三方聚合页或不能唯一识别职位的链接转入岗位检索路径。链接失效、岗位关闭、公司/届次不符或额度不足时停止该链接的填表；不要自行替换成名称相似的岗位。

## 入口与登录

- 优先使用用户或正式来源表提供的原链接。直接职位页按“岗位直达路径”处理并保留原链接；企业校招官网进入目标招聘项目；公众号和聚合页只用于提取官方招聘入口。
- 原链接失效时，查找同一企业官方招聘域名或官方发布渠道。第三方页面不能证明岗位仍开放或岗位全集。
- 当前 Chrome 只有空白页或未打开目标页面时，Agent 通过 Google Chrome 应用级界面自行导航到已知入口；不得要求用户代为打开或保持页面。
- 禁止使用 ChatGPT/Codex 的外部 Chrome 标签接管、调试或扩展桥接。应用级导航调用超时后，重新读取当前 Chrome 窗口；URL、标题或正文已经加载时视为导航成功并继续，不得仅凭超时重复开页或判定官网不可达。
- 官方入口重定向到招聘服务商的企业专属路径时，保存并复用重定向后的完整 URL。不能把服务商根域名、猜测的企业子域名或空白首页当作备用入口。
- 进入岗位检索前必须在官方招聘系统确认登录成功；公开页面只能用于定位官方入口，不能代替登录后的岗位核验。
- 未登录时先由执行子 Agent 打开登录流程。扫码、验证码、账号选择或注册选项交给用户；完成后续用同一子 Agent 和当前标签确认登录状态，不重复打开一套页面。
- 登录成功后先读取投递须知或个人中心，核实最大投递数、已投数和剩余额度，再开始岗位筛选与详情核验。

## 浏览器取数

动态招聘官网默认使用 Computer Use 的 Google Chrome 应用对象读取和操作浏览器界面，包括导航、筛选、翻页、滚动加载、打开详情和读取可见提示。每组确定性操作后获取一次最新页面状态；只有文本状态不足以判断时才截图。不要调用外部 Chrome 标签接口，也不要为同一状态同时获取完整可访问性树和截图。

完成登录核验后，优先确认同一官方站点是否能一次返回完整职位数据的接口或静态数据。能稳定取得时，批量读取一次并在本地按全部目标分类和关键词筛选、去重；再用登录后页面抽查职位 ID、名称、地点和可申请状态。只有无法取得完整数据时才逐页操作界面。不要让 Computer Use 与其他自动化方式并发控制同一窗口。宣传首页、热招职位和搜索摘要只能发现入口。

若应用级 Computer Use 不能取得可用页面状态，先重新读取 Google Chrome 应用并进行一次有区别的视觉回退；仍不可用才改用同一官方站点的公开接口。系统代理检查不作为前置门槛，也不能替代目标页面或官方地址的实际可达性证据。不得把“请用户打开、切换或保持网页”当作恢复步骤；无法覆盖的范围如实标记为待确认。

## 检索范围

目标届次和岗位方向来自当前消息或本地[`context.md`](../context.md)。必须区分正式校招、实习、社会招聘、境外项目和不同毕业届次，不能混入用户范围外的项目。

每家公司优先采用“完整数据一次取得”的路径：固定目标届次和招聘项目，取得全部职位后在本地展开目标方向分类、运行全部关键词、按职位 ID 或规范化详情链接去重，并逐项核实名称、届次、职责、要求、地点和可申请状态。若官网不能提供可验证的完整数据，再采用界面路径：

1. 固定目标届次和招聘项目；
2. 展开目标方向相关的完整职能分类；
3. 逐个使用目标方向关键词搜索，并与分类结果取并集；
4. 翻到最后一页、持续加载到总数稳定，或取得官网明确的全部结果；
5. 以职位 ID 或规范化详情链接去重；
6. 打开并集中的每个职位详情，核实完整名称、届次、职责、任职要求、地点和当前可申请状态。

同名但职位 ID、地点、业务线或职责不同的岗位分别保留。标题不明确但职责符合时可纳入并注明判断依据；职责明确不相关的结果排除。

只有完整数据路径已覆盖全部职位，或界面路径完成分类与关键词交叉检索、全量翻页或加载、去重和逐岗详情核验，才能声明岗位已找全。官网故障、登录受阻、筛选异常或总数无法确认时，记录已经覆盖的数据范围、分类、关键词、页数或最后加载位置以及未完成范围。

## 志愿限制

登录成功后，按以下来源顺序核实：投递须知或校招公告、个人中心已投记录与剩余额度、职位列表或详情提示、进入申请流程但尚未创建或提交申请时出现的限制。

- 保留官网原始口径，区分“最多投 N 岗”“N 个志愿”“每个项目/业务线 N 个”和累计上限。
- 页面可见时同时记录最大数、已投数和剩余数。
- 不把简历数量、收藏数、推荐数或搜索结果数当成投递上限。
- 若只有创建草稿后才显示上限，先说明会产生外部写入并取得授权；不为查上限点击最终提交。
- 多个招聘项目分别设限时逐项记录。
- 登录后仍无法确认时写`官网未明确，待确认`并列明已检查位置，不使用往届或第三方规则猜测。

## 工作地点

每个岗位从自己的职位详情页读取工作地点。不能用公司总部、宣讲城市、公司级城市范围、相似岗位或用户偏好代替。

多城市、园区、国家/地区、`全国分配`、`远程`或`地点待定`保留页面原文。前端暂时不可读时，可使用同一官方招聘域名为同一职位提供的数据，但必须用职位 ID 和完整名称核对；仍无法确认就标记`待确认`。

## 岗位检查点输出

公司层级：目标招聘项目、覆盖证据、最大投递数与口径、已投数、剩余数、未完成范围。

岗位层级：完整名称、职位 ID（页面可见时）、届次、工作地点、方向归类、职位详情或直接投递链接。只交付事实清单，不替用户推荐、排序或省略匹配项。
