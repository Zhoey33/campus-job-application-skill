# 飞书投递台账

仅在需要查询或写入正式台账时读取本参考，并同时读取本地[`context.md`](../context.md)。

## 阶段门槛

1. 确认`lark-cli`可用，执行有效的用户身份认证检查；不要用 bot 身份替代失败的用户身份。
2. 按需加载`lark-shared`、`lark-wiki`与`lark-sheets`，使用`context.md`中的正式链接只读解析 Wiki 节点。
3. 核对目标标题与底层类型，并读取最小表格范围确认访问。标题、类型或资源不符时停止写入，不按相似名称猜选。
4. 只在实际需要相应动作时检查读取或写入权限。缺少权限时报告准确 scope 或授权缺口；安装 CLI、增加全局权限或重新配置应用需用户授权。

上述检查和可执行的只读诊断由 Agent 自己完成，不能要求用户代跑命令或确认台账是否可访问。不得输出或保存 appSecret、access token、refresh token、验证码或 device code。台账门槛失败只阻塞台账操作，不撤销已经完成的找岗或表单工作。

## 查重与定位

在完整有效数据区按企业全称、常用简称和官网主体搜索。存在企业或志愿记录时补原行；只有确认无匹配记录后才新增，不能借用名称相近的企业行。

新增前读取表头、真实数据末行、相邻记录样式和公式，沿用现有的一企一行或一岗一行结构。序号按表中既有公式或编号规律生成，不凭对话心算行号。

正式入口线索缺失时，可只读查询`context.md`中的可选来源表；它只提供企业名称、入口、备注、行业或企业类型线索。岗位名称、届次、地点、职位状态、链接和志愿上限仍以企业官方招聘系统为准。

## 写入时点与字段

用户确认岗位后写入真实志愿和工作地点；表单状态变化时更新已有状态列；官网确认提交成功后才写`已投递`和实际投递日期。

每个已确认志愿至少维护：

- 企业名称和志愿顺序；
- 官网完整岗位名称；
- 该岗位详情中的工作地点；
- 职位直达链接（有对应列时）；
- 与实际阶段一致的状态（有状态列时）。

原表已有部门、行业类型、企业类型、内推码、来源、备注或日期列时，只写有可靠依据的值。未知字段沿用表内缺失值约定填写`待确认`或留空，不猜测。

台账独立的“资料填写完成”标记栏完成后写`✅`；它不等同于投递状态，不能替代`待审查`、`待提交`或`已投递`。

## 多志愿与结构修改

- 一岗一行时每个志愿单独占一行并保留企业名和准确顺序。
- 一企一行时优先使用现有第一、第二等志愿字段。
- 没有岗位或地点列时，新增列属于表结构修改。说明影响并取得用户确认后，才最小化新增并匹配相邻样式。
- 同一公司不同岗位的地点、链接和状态逐岗核对；不能把一个志愿的事实复制给其他志愿。

## 最小写入与回读

写入前重新读取目标区域，采用最小范围编辑，不重排无关数据，不覆盖用户备注、公式或链接。写入后：

1. 回读完整目标记录，核对企业、岗位、地点、链接、顺序和状态；
2. 再次搜索企业名称，确认未产生重复行；
3. 只有回读一致后才汇报`台账已更新`。

写入失败或权限不足时保留浏览器状态并报告，不能用本地副本冒充正式台账。只有用户明确要求同时维护本地 Excel 时，才加载`Spreadsheets`并写本地文件。
